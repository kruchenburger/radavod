# Своя копия: настройки входа

[English](self-deploy.md)

Это заметки для тех, кто разворачивает Radavod на своём аккаунте Cloudflare. Полный гайд будет позже, здесь три настройки, без которых вход не работает: без них никто не войдёт и никто не сможет завести семью.

В примерах адрес сайта — `family.example`. Подставьте свой.

## Настройки

| Настройка    | Вид        | Значение                                                             |
| ------------ | ---------- | -------------------------------------------------------------------- |
| `RP_ID`      | переменная | Домен сайта без `https://`, порта и пути: `family.example`           |
| `ORIGIN`     | переменная | Адрес ровно так, как его присылает браузер: `https://family.example` |
| `SETUP_CODE` | секрет     | Длинный случайный код, по которому хранитель заводит семью           |

`RP_ID` и `ORIGIN` записываются в `vars` конфигурации Wrangler вашей установки, рядом с `JURISDICTION` и `SAMPLE`. В `ORIGIN` нет косой черты в конце и нет порта. Сайт должен открываться по `https://` с этого домена: на адресе `*.workers.dev` или на втором домене войти не получится.

Выкладка заменяет все переменные тем, что написано в конфигурации, поэтому переменная, заданная только в панели Cloudflare, пропадёт при следующей выкладке. Держите обе в конфигурации.

Ключи доступа (passkeys) принадлежат `RP_ID`. Если потом перенести сайт на другой домен, все ключи, созданные для старого, там работать перестанут, и каждого участника придётся впускать заново. Выберите домен до того, как войдёт первый хранитель.

## Код установки

`SETUP_CODE` — секрет Worker, а не переменная: переменную видит каждый, кто может читать настройки Worker.

Что он делает:

- В новой установке впускает первого хранителя на странице `/setup`.
- Потом каждый новый код впускает ещё одного хранителя, один раз. Использованный код больше никого не впустит, поэтому его можно не убирать.
- Без кода или с кодом короче 20 знаков установка закрыта. Участники при этом входят как обычно.
- Страница установки даёт 10 попыток за 15 минут с одного адреса. Неверный код, использованный код и отсутствие кода получают одинаковый ответ.

Обычно участников, хранителей тоже, добавляют приглашением от хранителя. Код установки нужен для первого хранителя и для ещё одного, когда пригласить его некому.

### Как сделать надёжный код

Возьмите 32 случайных знака из генератора менеджера паролей и сохраните код там же: его придётся ввести на странице установки. Не придумывайте код сами и не берите пароль, который уже где-то используется.

Без менеджера паролей любая из этих команд выведет случайный код из 32 знаков (вторая — в PowerShell 7):

```sh
openssl rand -base64 24
```

```powershell
$bytes = [System.Security.Cryptography.RandomNumberGenerator]::GetBytes(24); [Convert]::ToBase64String($bytes)
```

Код не должен попадать в файлы репозитория, в коммиты `.env` и `.dev.vars`, в issue, чаты и снимки экрана.

### Как передать код Worker

```sh
npx wrangler secret put SETUP_CODE
```

Wrangler спросит значение и не покажет его. Секрет действует сразу и сохраняется между выкладками. Чтобы впустить ещё одного хранителя, задайте так же новый код и передайте его этому человеку по каналу, который читаете только вы двое.

Если выкладка идёт из CI, храните код секретом CI и передавайте его в `wrangler deploy --secrets-file` через временный файл или в `wrangler secret put` через стандартный ввод. Не пишите его в командную строку и не выводите в лог.

## Локальная разработка

Тесты и `wrangler dev` работают с `RP_ID`, равным `localhost`, и `ORIGIN`, равным локальному адресу, например `http://localhost:8787`. На `localhost` браузеры принимают ключи доступа без `https://`. Тесты задают свой код установки; локально подойдёт любой код от 20 знаков.
